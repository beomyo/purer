# Purer 桌面端缩略图刮削器

在 Windows 电脑上通过 WebDAV 直接给视频生成缩略图，写入与手机 App 共用缓存完全相同的目录。
电脑刮削完成后，手机打开对应文件夹即可直接命中缓存，不必让手机长时间挂机。

## 功能

- 登录 WebDAV，逐级浏览并选择「缓存根文件夹」和「要刮削的文件夹」
- 递归扫描子文件夹，生成的缩略图按原目录结构镜像保存
- 文件名与 App 一致：`HH.MM.SS_视频文件名.jpg`（例如 `00.10.00_vid.mp4.jpg`）
- 已有缩略图的视频自动跳过；中断或再次运行会从没做完的地方继续
- **源视频已被删除时，对应的无效缩略图会自动删除**：扫描文件夹时发现缓存里有 `.jpg`
  但源目录里已没有对应视频，会直接删除该缩略图（`--dry-run` 只列出、不删除）
- **所有失败视频**都会写入 `scraper.log` 和 `failed_videos.json`；后续普通运行自动跳过，
  运行 `python purer_scraper.py --retry-failed` 可单独重试
- **失败详情完整记录**：失败阶段、每次尝试的 ffmpeg/ffprobe 命令行（隐藏认证头）、
  退出码、错误输出末尾 15 行、文件大小、用时都会写入日志和 JSON，便于直接定位原因
- **并发进度按视频统一计量**：同时处理多个视频时，终端为每个任务保留一行，
  显示「第几帧 / 整个视频已用 / 当前操作已用 / 解码帧数」，心跳日志也按任务号输出
- 网络波动类失败会先自动重试一次，仍然失败才计入失败记录
- 永久性失败同时写成与 App 一致的 `<视频名>.failed-<原因>` 标记
- 抽帧频率与 App 一致：默认每秒 2 次（可设 1–20），**按文件夹**限速，默认 2 个并发（上限 4；App 最多 4）
- 只做远程抽帧，使用 HTTP Range 读取目标附近的数据；**不会下载/保存源文件，也不会从头解码整个视频**
- 超大 AVI 自动从 1MB 文件头读取时长，并用 `-use_odml 0` 在靠前位置取帧；不会去读尾部索引或整文件
- **支持 HLS（`.m3u8`）**：读取播放列表得到时长，只拉取目标时间点附近的分片，同样不下载整个视频
- 只用 Python 标准库，不需要 `pip install`

## 项目结构

```text
purer_scraper.py        启动脚本（仅入口，负责调用 src/cli.py）
src/                   实现代码
  cli.py               命令行参数与主流程
  scrape.py            扫描目录、并发生成缩略图/雪碧图
  ffmpeg.py            ffmpeg/ffprobe 调用、抽帧、卡死检测
  mp4window.py         卡死兜底：局部窗口读取
  webdav.py            WebDAV 客户端
  cache.py             缓存目录、缩略图与失败标记
  failures.py          失败记录与 --retry-failed
  failure_report.py    失败详情日志
  progress.py          并发任务进度与心跳
  console.py           终端颜色、进度区与日志
  ...（urls/errors/rate/retry/settings/constants/paths/runtime）
scraper_config.json    配置（首次运行后生成，含明文密码）
scraper.log            运行日志
failed_videos.json     本地失败记录（含详细失败信息）
```

所有数据文件仍与启动脚本同级；`python purer_scraper.py` 的使用方式不变，
也不需要在 `src/` 里运行。

## 环境要求

- Windows 10 / 11
- Python 3.8 或更高版本
- ffmpeg 与 ffprobe（脚本会自动在 PATH、`D:\Program Files\Environment\ffmpeg\bin`
  等常见位置查找，也可以用 `--ffmpeg` / `--ffprobe` 指定）

## 支持的视频格式

按扩展名识别（不区分大小写）：

```text
.mp4 .m4v .mkv .webm .mov .avi .wmv .flv
.ts .m2ts .mpg .mpeg .3gp .3g2 .ogv .m3u8
```

WebDAV 返回的 MIME 以 `video/` 开头的文件也会被当作视频，即使扩展名不在上表里。
`.m3u8` 是 HLS 播放列表：ffmpeg 先读列表拿到总时长，再按百分比只请求对应分片；
分片本身可以是 `.ts` 或 fMP4（`.m4s`）。直播流（播放列表里没有 `#EXT-X-ENDLIST`）
没有稳定时长，只会用 `--fallback-seconds` 附近的位置取帧，不建议用于刮削。

> 手机 App 自身的视频扩展名列表里没有 `.m3u8`，所以这类缩略图只有桌面端和
> 任何按文件名读取缓存的工具能用；App 不会把 `.m3u8` 当视频点播。

## 使用

在该目录打开命令行执行：

```bat
python purer_scraper.py
```

然后按提示：

1. 输入 WebDAV 地址，例如 `https://nas.example.com/dav/`
   （必须与 App 里该服务的地址完全一致，缓存镜像的相对路径以它为基准）
2. 首次输入用户名和密码；密码会明文保存到 `scraper_config.json`，以后不再询问
3. 选择缓存根文件夹（`0` 使用当前目录，序号进入子目录，`mkdir 名称` 新建目录，
   也可以直接粘贴完整 URL 跳转）
4. 选择要刮削的文件夹
5. 查看摘要，按 Enter 开始；输入 `m` 可重新选择文件夹
6. 失败视频会记录到 `failed_videos.json`，后续运行自动跳过；可运行 `python purer_scraper.py --retry-failed` 单独重试

上次使用的地址和文件夹会保存在 `scraper_config.json`，下次直接回车沿用。
运行日志写入同目录的 `scraper.log`（日志文件不包含终端颜色代码）；
失败视频同时记录到同目录的 `failed_videos.json`，普通运行据此跳过。
每次运行会写入开始/结束分隔和结束汇总，便于区分多次运行。
按 Ctrl+C 会取消排队中的视频并终止正在运行的 ffmpeg，不会等整个文件夹跑完。

### 终端界面

- 交互式终端里会显示颜色、分隔线和实时进度区；`NO_COLOR=1` 可关闭颜色
- 进度区第 1 行显示当前文件夹的完成数、新增数、失败数和已用时间；
  之后**每个并发任务固定一行**（任务号、视频名、阶段/第几帧、视频已用、当前操作已用、
  解码帧数），多路并发时不会互相覆盖，日志会正常打印在进度区上方
- 每个视频开始处理、读到的时长/取帧位置、完成用时都会写日志；运行中的视频每 10 秒写一条
  心跳，格式为 `[任务 #N] 视频名：取帧 3/25 · 视频已用 134s · 当前 18s · 帧 42 · 已解码 1.2s`。
  无论并发几路，「视频已用」始终从该视频开始处理算起，重试和多次 ffmpeg 调用都不会归零，
  因此每个视频的进度可以直接横向对照
- 判定卡死后会自动改用「局部窗口」补图，日志会写明改为局部窗口以及用时
- 非交互环境（例如计划任务）会自动关闭颜色和进度行，只输出纯文本日志

## 缓存结构

假设 WebDAV 服务根是 `https://host/dav/`，选择：

- 缓存根：`https://host/dav/cache/`
- 源文件夹：`https://host/dav/media/movies/`

则：

```text
https://host/dav/media/movies/vid.mp4      （源视频，10 分钟）
https://host/dav/cache/media/movies/00.10.00_vid.mp4.jpg
```

这正是 App「缩略图缓存与刮削 → 缓存文件夹」读取的格式，所以无需再在手机上刮一遍。

如果视频文件名本身已经以 `HH.MM.SS_` 开头，脚本不会再叠加时长前缀，与 App 行为一致。

## 雪碧图模式

启动时会询问「生成 [1] 缩略图 [2] 雪碧图」；非交互环境用 `--sprite` 直接指定。
雪碧图与普通缩略图保存在**同一个镜像目录**、同样以 `.jpg` 结尾，区别只在文件名
末尾增加了 `~列x行`：

```text
https://host/dav/cache/media/movies/00.10.00_vid.mp4~5x5.jpg
```

- 默认 `5x5`（25 帧），用 `--sprite-grid` 调整；单格最大边长用
  `--sprite-width`（默认 320）。
- **默认只处理时长超过 300 秒的视频**：短片读完时长后直接跳过（计入「时长不足跳过」，
  不算失败、不写失败标记），下次运行仍会重新判断。用 `--sprite-min-duration 秒数`
  或 `scraper_config.json` 里的 `sprite_min_duration` 调整，`0` 表示不限制；
  普通缩略图模式不受此限制。`--dry-run` 不读取视频时长，短片也会出现在待处理列表中。
- 雪碧图总大小上限 **1MB**：超过时自动降低 JPEG 质量，仍超出再缩小整张图；
  App 按实际图片宽高 ÷ 列/行得到单格尺寸即可。
- 在视频 **10%–95%** 区间内均匀取点（含两端）：第 i 帧位置 =
  时长 × (0.10 + 0.85 × i / (N-1))，N = 列×行，
  所以帧间隔 = 0.85 × 时长 / (N-1)。App 只需从文件名读列/行，再结合时长前缀即可还原。
- App 解析顺序：去掉 `.jpg` → 匹配末尾 `~(\d+)x(\d+)` → 剩下的部分按普通缩略图
  规则（去掉 `HH.MM.SS_` 前缀）得到视频名。
- App 会把雪碧图转成循环 GIF 动画作为缩略图：按列/行切分，用时长前缀和
  `0.85 × 时长 / (N-1)` 作为每帧间隔还原真实播放速度。文件夹内没有雪碧图的视频
  保持原缩略图；也可以点工具栏「雪碧图转动画」手动为整夹生成。
- 代价：每个视频要取 N 帧（N = 列×行），流量和耗时约为普通缩略图的 N 倍；
  必须能读到视频时长，读不到直接失败；服务器不支持 Range 时也不做雪碧图。
- 切换到新格子后，新图上传成功会自动删除同视频的旧格子雪碧图；新图失败时旧图保留。
- 雪碧图失败不写失败标记，也不读写缩略图的失败记录；下次运行只要还没有雪碧图就会自动重试。
  只有对应模式的文件已存在时才跳过，两种模式互不影响。

## 无效缩略图清理

扫描每个源文件夹时会同时读取缓存的镜像目录。如果某个 `.jpg` 在源文件夹里找不到
对应的视频（去掉 `.jpg` 后、以及再去掉 `HH.MM.SS_` 时长前缀后都不存在），说明原视频
已被删除，这张缩略图无效，脚本会**直接删除**。

- 只在该源文件夹能正常列出时才删除；列目录失败、认证失败或网络错误时不会删除任何文件。
- 判断忽略大小写，并做 Unicode NFC 归一化（中文文件名不会因编码形式不同误删）；源目录里存在同名文件（即使扩展名不是常见视频格式）就保留缩略图。
- 雪碧图同样是 `.jpg`，也按同样规则判断和清理（`~列x行` 后缀不影响视频名匹配）。
- **源子文件夹被删除时**：如果缓存镜像目录里还有对应的子目录，会递归删除该缓存子目录
  （含其中的普通缩略图、雪碧图、失败标记等），并在日志里写明。只在父目录能正常列出时比较，
  避免网络/认证问题导致误删。
- `--dry-run` 只打印「待删除无效缩略图 / 无效缓存目录」，不会真的删除。
- 如果**你选择的源根文件夹本身**被删除，仍不在扫描范围内（扫描从选定的源文件夹开始）；
  但它的子文件夹被删除，会在父目录扫描时清理。

## 失败记录与失败标记

### 详细失败日志

除了终端里的一行摘要，每次失败都会在 `scraper.log` 写入一块「失败详情」，包括：

- 视频名、源地址、文件大小、缓存目录、处理模式（缩略图/雪碧图）；
- 失败阶段（读时长 / 抽帧 / 第几帧 / 局部窗口 / 上传）、目标时间点、是否可重试；
- 整个视频的用时与尝试次数；
- **每一次尝试**的命令行（`Authorization` 头自动替换为 `<已隐藏>`）、退出码、
  超时上限、标准输出字节数、错误输出末尾 15 行。

同样的内容会以 `details` 字段写入 `failed_videos.json` 的对应条目
（`phase`、`elapsed`、`size`、`attempts` 等），`--retry-failed` 再次失败时也会更新。
雪碧图模式不写 App 失败标记，但失败详情同样完整记录。

### 本地失败记录（所有失败）

每个失败的视频（包括超时、网络错误等临时失败）都会写入同目录的 `failed_videos.json`。
后续普通刮削会自动跳过这些视频，不再反复等 20 秒超时；需要重试时使用
`python purer_scraper.py --retry-failed`。重试成功或发现已有缩略图后，记录会自动移除。
删除 `failed_videos.json` 可以让普通刮削重新尝试这些本地记录对应的视频；
App 的永久失败标记仍然会跳过，重试它们请用下面的重试脚本。

### App 失败标记（永久性失败）

无法抽帧、且再次尝试也不会成功的视频，会在**缓存目录里、缩略图旁边**留下一个标记文件：

```text
<缓存根>/media/movies/<视频名>.failed-<原因>
```

例如：

```text
https://host/dav/cache/media/movies/broken.mp4.failed-noframe
```

标记内容与 App 相同，三行文本：

```text
2026-11-22T01:23:45.123456Z
noFrame
Invalid data found when processing input
```

- **只有永久性失败才写标记**：`noframe`（无法解码/格式不支持）、`notfound`（404）。
- 超时、限流（429）、认证失败（401/403）、服务器错误（5xx）、网络错误等属于**临时失败**，
  不写 App 标记，但会记录到 `failed_videos.json`，后续普通运行会跳过；
  可用重试脚本再次尝试。
- 已有缩略图的视频如果残留标记，脚本会自动删除该标记，并移除本地失败记录。
- 写标记时如果旧标记的原因不同（例如之前是 `unknown`，现在是 `noframe`），旧标记会被删除。
- 标记文件不是 `.jpg`，App 的缩略图索引不会把它当成缩略图。

上一版使用的 `_purer_scraper_failed.json` 不再读写；它只是普通 JSON 文件，可以手动删除。

## 手动重试失败项

执行：

```bat
python purer_scraper.py --retry-failed
```
重试脚本会合并 `failed_videos.json` 与缓存目录中的 App 失败标记并列出：

- `a`：全部重试
- `1 3 5`：只重试这几个序号
- `d 1 3`：忽略并删除这几个本地记录和缓存标记
- `q`：返回

重试成功后会删除标记和本地记录；永久性失败会重新写回标记；
临时性失败会保留本地记录，不会让失败列表丢失。
`--retry-failed --dry-run` 只列出失败记录，不重试；`--limit N` 限制本次最多重试 N 个。
密码使用 `scraper_config.json` 中保存的值，重试时不再询问。
> `--retry-failed` 在非交互环境（例如计划任务）下会自动重试全部失败项。

## 抽帧频率、超时与重试

- 每个文件夹内，两次抽帧开始之间至少间隔 `1/rate` 秒，默认 `2` 次/秒，范围 `1–20`。
- 默认同时处理 `2` 个视频；`--jobs` 的上限是 4（与 App 一致）。
  限速仍然生效，所以并发提高不会突破每秒的请求预算。
  日志显示 4 并发时部分 WebDAV 服务更容易读时长超时，所以桌面端默认用 2；
  服务器足够快时可以用 `--jobs 4`。
- 读取视频时长默认超时 20 秒，单次抽帧默认超时 45 秒。可以在
  `scraper_config.json` 里直接改：
  ```json
  "probe_timeout": 20,
  "extract_timeout": 45
  ```
  也可以用 `--probe-timeout` / `--extract-timeout` 临时覆盖。
- **卡死判定**：ffmpeg/ffprobe 连续 75 秒没有任何进展就中止当前这一步，不再一直等到总超时。
  服务器一直在慢慢发流量、ffmpeg 却始终解析不出画面时（后台看得到流量但日志不动），
  日志会写明「连续 Ns 没有解码进展」。卡死不重试（重试只会再卡一次）。
- **卡死兜底（局部窗口）**：判定卡死后不会直接放弃，而是只读文件头（含 MP4 索引）
  和取帧位置附近约 48MB 数据，拼成本地文件抽帧；每个视频最多下载约 72MB，
  绝不下载整个文件。成功则日志写「局部窗口取帧成功」，失败才记入 `failed_videos.json`。
  只有 MP4 索引在文件头部时才能这样补图；AVI/HLS 或索引在尾部时仍按原失败处理。
  不需要时用 `--no-window-fallback` 关闭。
  默认值可以在 `scraper_config.json` 里改 `stall_timeout`，或用 `--stall-timeout` 覆盖；
  `0` 表示关闭卡死判定。
- **只使用输入端定位（HTTP Range）**：`-ss` 放在 `-i` 之前，让服务器只返回目标附近的数据；
  不再从头解码到百分比位置，也不会把源视频下载到本地。
- **超大 AVI 自动处理**：
  - 先用 `Range: bytes=0-1048575` 只读 1MB 文件头，解析 `avih` / `dmlh` 得到时长；
  - ffmpeg 加 `-use_odml 0`、`-probesize 5M`、`-analyzeduration 5M`，避免读 OpenDML 尾部索引；
  - 在 `fallback-seconds`、120、180、300 秒几个靠前位置分别取一帧，优先选较大的 JPEG，
    避免开头黑屏或空白画面；全部候选都很小则按失败记录，方便手动处理。
- **HLS（`.m3u8`）不做 Range 探测**：播放列表只有几 KB，直接读取；
  ffprobe 从 `#EXTINF` 汇总出时长，抽帧时 `-ss` 仍然放在 `-i` 之前，
  ffmpeg 会跳到包含目标时间点的分片，不会从头拉完所有分片。
  分片和密钥（`#EXT-X-KEY`）沿用同一个 Basic 认证头，所以播放列表里的地址
  需要与源 WebDAV 同源；外部 CDN 分片若需要单独鉴权会取帧失败。
- 启动前会用 `Range: bytes=0-0` 探测服务器。**不支持 Range 时不读取视频时长**，
  直接从 `--fallback-seconds`（默认 3 秒）附近取帧，避免 ffprobe/ffmpeg 顺序读取整个大文件。
- **失败兜底默认开启**：ffprobe 读不到时长（超时、格式不支持等）时，不再直接失败，
  而是按 `--fallback-seconds` 取一帧，此时文件名不带时长前缀；
  目标百分比位置抽帧超时时，会改用接近开头的位置再试一次。
  需要恢复旧行为时加 `--no-fallback-retry`。
- **网络波动重试**：默认 `--retries 1`。超时、5xx、429、上传失败等临时问题会自动再试一次；
  第二次尝试的抽帧超时翻倍（上限 300 秒），适合较大的视频文件。仍然失败才计入
  `failed_videos.json`。`noframe` / `notfound` / 认证失败等永久性问题不重试。
- 需要让普通刮削重新尝试已记录的视频时，可以用重试脚本；删除 `failed_videos.json`
  也会让这些视频重新参与普通刮削（App 永久标记仍会跳过）。

## 常用参数

| 参数 | 说明 |
| --- | --- |
| `--dry-run` | 只列出待处理视频、待删除的无效缩略图或失败记录，不抽帧、不上传、不删除（建议先配合 `--limit 5` 试跑；`--retry-failed --dry-run` 只列出失败记录） |
| `--limit 5` | 本次最多处理 5 个视频 |
| `--percent 80` | 取帧位置，视频时长的百分比（1–99，默认 80） |
| `--rate 2` | 每个文件夹每秒最多抽帧次数（1–20，默认 2） |
| `--width 320` | 缩略图最大边长（像素） |
| `--sprite` | 生成雪碧图而不是缩略图（交互运行时也会询问；默认缩略图） |
| `--sprite-grid 5x5` | 雪碧图格子（列x行），默认 5x5，总帧数上限 25 |
| `--sprite-width 320` | 雪碧图单格最大边长（像素），默认 320；整张图上限 1MB |
| `--sprite-min-duration 300` | 雪碧图只处理时长超过该秒数的视频（默认 300，也可写在配置 JSON；`0` 表示不限制；缩略图模式不限制） |
| `--jobs 2` | 同时处理的视频数（1–4，默认 2；App 上限为 4；服务器较弱时可降到 1） |
| `--retries 1` | 网络类失败的重试次数，默认 1；`0` 关闭（永久性失败始终不重试） |
| `--retry-failed` | 只处理 `failed_videos.json` 和 App 失败标记中的视频；`--limit` 限制本次重试数 |
| `--no-fallback-retry` | 关闭失败兜底（默认开启） |
| `--probe-timeout 20` | 读取视频时长的超时秒数（默认 20，也可写在配置 JSON） |
| `--extract-timeout 45` | 单次抽帧的超时秒数（默认 45，也可写在配置 JSON；重试时翻倍） |
| `--stall-timeout 75` | 连续多少秒没有任何进展就判定该视频卡死并中止（默认 75，也可写在配置 JSON；`0` 关闭） |
| `--no-window-fallback` | 关闭卡死兜底（默认开启：卡死后只读索引和取帧位置附近约 48MB 拼成本地文件抽帧） |
| `--password` | 源 WebDAV 密码；不填则使用已保存的密码，首次输入后明文保存到配置 |
| `--cache-password` | 缓存 WebDAV 密码；默认与源服务相同 |
| `--proxy http://127.0.0.1:7890` | WebDAV 和 ffmpeg 都走指定代理；默认直连，不使用系统代理 |
| `--insecure` | 忽略 HTTPS 自签名证书错误 |
| `--ffmpeg PATH` / `--ffprobe PATH` | 手动指定 ffmpeg / ffprobe |

完整的非交互示例：

```bat
python purer_scraper.py ^
  --server https://host/dav/ ^
  --user alice --password secret ^
  --cache-folder https://host/dav/cache/ ^
  --source-folder https://host/dav/media/ ^
  --rate 2 --width 320 --jobs 2
```

## 说明

- 只支持 WebDAV（Basic 认证），不支持 SMB。
- `.m3u8` 需要 ffmpeg 能直接访问播放列表和分片（同一个 WebDAV 服务、同一套认证）。
- 源服务地址、缓存服务地址都要与 App 中的服务配置一致，否则镜像路径会对不上。
- 缓存文件夹必须是 App 里配置的同一个「缓存文件夹」；选择它的**根目录**，不要选到某个镜像子目录。
- 默认直连、不走 Windows 系统代理，与手机端行为一致；需要代理时用 `--proxy`。
- 抽帧只使用输入端定位（`-ss` 在 `-i` 前），依靠 HTTP Range 读取目标附近的数据；
  **不会在输出端从头解码，也不会下载/保存源文件**。服务器不支持 Range 时，
  直接改用 `--fallback-seconds` 附近取帧，避免读取整个大文件。
- 失败原因和详细上下文会同时写入终端、`scraper.log` 和 `failed_videos.json`；永久性失败还会写 App 标记。
- 失败兜底开启时，读时长超时的视频会先尝试用接近开头的位置生成缩略图，
  仍失败才按临时失败处理；不会因为读不到时长就直接跳过。
- 超大 AVI 即使 ffprobe 超时，也会通过文件头得到时长，并在靠前位置选一张非黑屏画面；
  不会为了取帧而读取整个 30GB 文件。
- 缩略图是 JPEG，最大边长默认 320 像素，与手机端 App 的显示需求相当。
- 按你的要求，`password` / `cache_password` 以**明文**保存在 `scraper_config.json`；
  如果需要更换密码，用 `--password 新密码` / `--cache-password 新密码` 运行一次即可覆盖。
