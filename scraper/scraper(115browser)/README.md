# 115 缩略图 / 雪碧图生成器

一个**独立**的 Tampermonkey / ScriptCat 用户脚本，只做一件事：

> 在 115 网页里，用浏览器 WebCodecs 解码 115 转码 HLS，批量生成
> Purer 兼容的雪碧图和普通缩略图，然后**直接 PUT 到 WebDAV 缓存**。

没有后台服务、没有 ffmpeg、没有 115Master 的播放器/字幕/封面等代码。

处理结束后，再用原来的 `purer_scraper.py` 跑一遍即可补齐浏览器没有处理的视频
（没有 115 转码、解码失败、网络失败等）。本脚本**不修改** purer-scraper。

---

## 为什么快

原来 purer-scraper 一条视频要：

```text
1 次 ffprobe + 25 次 ffmpeg 远程 Range 抽帧 + 拼接
```

本脚本一条视频是：

```text
1 次 115 m3u8 + 25 个最低画质 TS 分片（WebCodecs 解码）+ Canvas 拼图
```

只使用 115 的**最低画质**转码源，单帧只需要 320px 左右；不需要启动 25 个进程，
不需要从头解码整个视频。

要求 Node.js >= 20.12、pnpm。

```bash
cd "D:\Program Files\Desktop\scraper"
pnpm install
pnpm build
```

产物：

```text
dist/115-thumbnail-scraper.user.js
```

在 Tampermonkey / ScriptCat 里新建脚本并粘贴该文件，或把文件拖进扩展。
也可以把文件放到本地后通过扩展的「导入」安装。

## 使用

1. 打开 115 的文件夹页面。
2. 点右下角的 **缩略图** 按钮，或油猴菜单里的「打开缩略图/雪碧图生成器」。
3. 首次打开会自动弹出配置：

   - **WebDAV 缓存根**：默认已填 `http://10.2.31.10/dav/UC/cache`。
   - **要处理的 115 文件夹**：可以直接填 115 挂载下的 WebDAV 文件夹地址，例如
     `http://10.2.31.10/dav/115/要处理的文件夹`；也可以点旁边的「浏览 DAV」，
     目录树直接来自 WebDAV（不读 115 页面/浏览器当前目录）。
     脚本以这个地址为准读取目录树，并用它的相对路径在 115 API 里定位 pickcode；
     **不需要在 115 页面里选择文件夹，也不读取浏览器当前目录**。
     目标缓存自动镜像为 `缓存根/115/要处理的文件夹/`，与 Purer 的规则一致。
   - **用户名 / 密码**：缓存和源 WebDAV 的 Basic 认证账号（你的环境两者相同）。
   - 默认勾选「递归子文件夹」，会处理该地址下的全部子目录。
   - 开始前会按地址里的路径在 115 API 中定位目录；若账号里的实际路径多出前缀
     （WebDAV 挂载的是子目录），会尝试按「路径后缀」在 115 目录树中唯一定位。
   - **参数**：
     - 雪碧图 + 缩略图 / 只雪碧图 / 只缩略图；
     - **时长低于「雪碧图最短时长」的视频只生成缩略图**（默认 300s，面板可改，0 = 不限）：
       「雪碧图 + 缩略图」模式仍会生成缩略图，「只雪碧图」模式则整个视频跳过；
     - 格子（默认 `5x5`）、雪碧图单格最大边长（默认 `320px`）、雪碧图上限（默认 `1024KB`）；
     - 雪碧图最短时长（默认 `300s`，0 = 不限）；
       有雪碧图时缩略图直接用雪碧图最后一帧，不再单独取帧；单独取帧的缩略图固定 320px 长边，与 Purer 一致；
     - 缩略图取帧位置（默认 80%，只在没有雪碧图时生效）；
     - 视频并发、单视频解码并发：各自 1–4，默认 **3 × 3**；
     - 跳过已存在（默认开启）。
4. 「扫描目标文件夹」只预览**目标文件夹的直接视频**，并读取缓存标记已存在产物；
   它不递归，也不处理任何文件。
5. 点「开始处理（逐文件夹）」：
   - 按文件夹逐个扫描：一个文件夹的视频生成/上传完成后，才进入下一个文件夹；
   - 不会先把整棵目录树全部收集完再处理，文件夹多时不会一次性堆出大量任务行；
   - 当前文件夹的视频显示在任务表里；成功、跳过、失败、进行中在下方分类日志里累计；
     顶部状态栏实时显示成功占比（成功数 / 需处理的视频数，跳过的不计入）；
   - 失败视频只写入「失败记录」，不写 Purer 的失败标记、不做自动兜底；
   - 某个文件夹读取/上传失败只会跳过该文件夹并继续后面的目录，不会终止整批；
   - 再点一次「开始处理」会重新遍历，已存在的按「跳过已存在」跳过，失败项重试；
   - 点「取消」会停止继续扫描下一个文件夹，并让正在解码的帧完成当前分片后停止。
6. 处理完成后，运行原来的 `python purer_scraper.py` 补齐未处理的视频。
7. 失败记录按「目录 + 视频」去重，只保留每个视频最新的一条；重试成功或缓存已存在时会自动移除。
   可以在面板里展开，点「导出 JSON」保存，方便之后核对。
8. 点「重试失败项」只重试失败记录里、目标文件夹下的视频，不用重新扫整棵树。
9. 面板支持按 Esc 关闭。
10. 「测试连接」会依次检查缓存根、115 文件夹地址、115 API 根目录的条目数，以及该路径能否在 115 API 中定位；
    若 API 根目录是空的，说明浏览器登录的 115 账号与 WebDAV 挂载不是同一份数据，pickcode 无法获取。

## 产物命名与规则

与 Purer / 手机 App 完全一致：

```text
缓存根/115 在 WebDAV 的前缀/115 文件夹路径/
  HH.MM.SS_视频名.jpg              # 普通缩略图
  HH.MM.SS_视频名~5x5.jpg          # 雪碧图
```

- 雪碧图仅对 **时长 ≥ 雪碧图最短时长**（默认 300s，面板可改，0 = 不限）的视频生成；时长更短的只生成缩略图；
- 雪碧图在视频 **10%–95%** 区间均匀取 `cols × rows` 帧（含两端）；
- 默认 5x5、雪碧图单格 320px、JPEG 上限 1MB；
- 有雪碧图时，缩略图直接取雪碧图最后一帧（约 95% 位置），不额外取帧；
- 只有缩略图时，按 80% 位置单独取帧，最长边固定 320px；
- 雪碧图会先降 JPEG 质量、再按比例缩小，尽量压到上限内；仍超限时会在任务行里提示；
- 视频名本身已经带 `HH.MM.SS_` 前缀时不会重复叠加；
- 「跳过已存在」按视频名匹配，兼容不同时长前缀；
- 目标目录不存在时，上传前会用 MKCOL 自动逐级创建。

## 说明与限制

- **只支持 115 已转码的 H.264 / MPEG-TS HLS**。没有 HLS、fMP4、加密 HLS、
  使用了 BYTERANGE 的播放列表会在失败记录里写明原因，交给 purer-scraper 处理。
- 115 的 VOD 跨域授权偶尔需要先在 115 官方/Master 播放器里打开一次该视频。
  授权缺失时该视频会失败；重新打开播放器后再点「开始处理」即可重试。
- 默认递归处理目标文件夹的全部子目录。目标缓存目录会按相对路径镜像，例如
  `.../115/Pack From Shared/獣会/子目录/文件.jpg`；中文和空格逐段 `encodeURIComponent`。
- 递归时以「要处理的 115 文件夹」地址的真实 WebDAV 目录树为准，再用名称到 115 API 里匹配
  pickcode（名称会做 `NFC` 规范化和大小写兜底）；源 WebDAV 不可用时退回 115 API 递归。
  如果某个子目录/文件在 115 API 里找不到对应项，会写入日志并跳过，不会猜路径。
- 直接在前端上传到 WebDAV，使用 Basic 认证；默认地址是 HTTP，密码在局域网内
  明文传输，请只在可信网络使用。
- 账号密码保存在 Tampermonkey 的脚本存储里（明文），与 Purer 的
  `scraper_config.json` 类似。
- 脚本声明 `@connect *`，因为 HLS 分片域名和 WebDAV 地址都可能变化；脚本只会把
  115 相关请求发往 115 的域名，把图片 PUT 到你配置的 WebDAV 地址。
- 失败记录只保存在浏览器本地，最多 500 条；不写 `<视频名>.failed-<原因>`。
- 多个 115 标签页同时点「开始处理」会重复解码/上传；脚本只会在启动时提示一次，不会强制阻止。
- 开始处理前会按「要处理的 115 文件夹」地址里的相对路径，在 115 API 中逐级解析 cid；
  解析不到时会明确报错并停止，不会悄悄换成根目录处理。该路径必须与 115 账号内的目录一致。
- pickcode 只能从 115 API 获取，所以**浏览器登录的 115 账号必须与 WebDAV 的 115 挂载是同一份数据**。
  如果「测试连接」显示 115 API 根目录为空、而 WebDAV 有内容，说明两边不是同一账号/根目录（或挂载的是分享目录），
  这种情况下无法生成缩略图；需要把 WebDAV 指向该登录账号的文件根目录，或用同一个 115 账号登录。
- 页面刷新/关闭会中断当前浏览器任务；已上传的文件下次会被「跳过已存在」识别。

需要 Chrome 130+ / 115Browser 35+ 等支持 WebCodecs 的浏览器。

## 递归扫描、逐文件夹处理与并发

- **逐文件夹**：开始处理时，`src/collector.ts` 的 `walkFolders()` 扫描一个文件夹后立即
  调用处理回调；该文件夹的视频全部生成/上传完成后，才递归下一个文件夹。不会预先把
  整棵树的所有视频收集到内存里。
- **目录结构**：先并行读取起始 cid 的 115 API 条目和「要处理的 115 文件夹」地址的真实
  子项；每一级的子目录名去 115 API 里找 `cate_id/fid`，视频名找 `pickcode`。
  这样即使 115 API 的 `file_type` 字段不完整，也能用真实 WebDAV 树兜底；源 WebDAV
  不可用时只用 115 API 递归。
- **中文/特殊字符**：匹配时做 Unicode NFC 归一化；拼 WebDAV 路径时逐段
  `encodeURIComponent`，所以 `獣会`、`Pack From Shared` 这类名字不会乱码。
- **并发**：视频并发与单视频解码并发各自可设 1–4，默认 **3 个视频 × 3 路解码**；
  两者不再互相限制。并发越高越吃带宽/CPU，网络不稳时调低即可。
- **起始文件夹**：不再读取浏览器当前目录或 cid。开始前只按用户填写的 WebDAV 地址解析出
  115 内相对路径，再用 `resolveCidByPath()` 在 115 API 中逐级定位起始 cid；定位失败会提示
  该地址与 115 账号内的目录不一致，不会退回根目录猜。
- **空源目录兜底**：源 WebDAV 目录读到 0 项、但 115 里有内容时，会改用 115 目录结构；
  单个 115 目录读取失败时只跳过该文件夹，不会对每个条目刷一条“找不到”。
- **分页**：115 列表按服务端实际返回的条数翻页；响应带 `count`（总数）时会继续翻页，
  避免服务端限制单页大小时静默漏掉文件和子目录。
- **日志分类**：下方日志有「进行中 / 成功 / 跳过 / 未转码 / 失败 / 信息」六个分类，各自显示数量；
  「进行中」实时读取当前文件夹正在解码的条目，其余分类保留本次运行的历史（最多 1000 条）。
  日志标题另外显示「缩略图成功 N · 雪碧图成功 M」，把两种产物分开统计。
  115 没有转码的视频无法获取，单独记在「未转码」分类；取帧超时、解码失败等其他雪碧图问题记在「失败」里。
  顶部成功占比的「总数」不含跳过（缓存已存在）的视频。
  任务表当前文件夹最多渲染 300 行，超出会提示，完整结果看分类日志。
- **播放列表重试**：`/api/video/m3u8/` 返回 403/429/5xx 或网络抖动时，会退避重试（最多 3 次，
  间隔 0.8s / 2s，并带随机抖动；一个视频遇到 403 时其他视频也会一起冷却，避免继续触发风控），
  GM 请求会补 `Referer`/`Origin`。403 的响应体如果是 115 的 JSON 错误，会区分「未转码」
  （不重试，记入未转码分类）和「登录失效/请求过快」等临时错误（继续重试）；
  重试后仍是 403、正文又没有临时错误提示时，按「115 未生成转码播放列表」归入未转码分类。
- **取帧重试**：单帧取不到或超时时，先在原时间点重试（网络读片失败）；仍失败则换 ±0.5s 的
  附近帧，最后兜底接受该分片解码出的第一帧；雪碧图允许少量帧缺失（空格子留黑），
  任务行会注明「雪碧图缺少 N 帧」，缺帧过多时才判失败。
- **失败记录**：解码/网络/上传失败的视频只记录在浏览器本地，不写 Purer 的失败标记；
  同一目录下同一视频只保留最新一条，成功/跳过时自动移除；「重试失败项」只处理目标文件夹的失败记录；
  处理完后跑 purer-scraper 会跳过已生成的文件、补齐失败项。

## 开发

```bash
pnpm type-check   # tsc
pnpm test         # vitest（HLS 解析、115 API、WebDAV 上传、命名/取点）
pnpm build        # 生成 userscript
pnpm dev          # Vite 开发
```

目录：

```text
src/
  main.ts            入口（只在顶层窗口注入）
  ui.ts              配置面板、任务表、分类日志、失败记录
  collector.ts       逐文件夹递归扫描（115 API + 源 WebDAV 树）
  sourceFolder.ts    从「要处理的 115 文件夹」WebDAV 地址解析 115 内路径
  api115.ts          115 文件夹列表、路径反查、pickcode → m3u8
  webdav.ts          GM 请求实现的 WebDAV PROPFIND/MKCOL/PUT
  runner.ts          扫描结果 → 解码 → 拼图 → 上传 → 失败记录
  sprite.ts          取点、Canvas 拼图、JPEG 压缩
  cacheName.ts       Purer 命名规则、缓存匹配
  hls.ts             极简 m3u8 主列表/媒体列表解析
  clipper/           从 115Master 移植的 MPEG-TS + WebCodecs 解码器
  settings.ts        GM 设置
  failures.ts        GM 失败记录
  __tests__/         Vitest
```

`src/clipper/` 来自 115Master 的缩略图取帧实现（MIT），只保留了 TS 解复用、
VideoDecoder、分片 Range 读取等必要部分，去掉了播放器相关代码。
